# AI语音研究访谈平台

这是一个完全在本机运行的网页式研究访谈原型。它不作诊断，也不根据说话方式判断参与者的身份或疾病。

## 从GitHub获取

克隆仓库时需要同时取得CosyVoice子模块：

```bash
git clone --recursive <仓库地址>
```

仓库不包含模型权重、参与者数据、录音或Docker镜像。第一次安装需要联网下载依赖和模型；完成后可以断网运行。

## 解压后一键安装

Windows 10/11用户解压轻量安装包后，双击 `一键安装环境并启动.bat`。安装器会自动：

1. 检查磁盘空间，并自动选择CPU或NVIDIA GPU模式；
2. 安装缺少的Git、Python 3.11、FFmpeg、Docker Desktop和Ollama，并更新Ollama以支持RTX 50系列；
3. 下载官方CosyVoice源码；
4. 构建本地语音服务，并下载CosyVoice、SenseVoice与开源Qwen3模型；
5. 实际加载Qwen并检查是否进入NVIDIA显存，然后打开本地访谈网页。

第一次安装需要联网，并建议至少保留45GB磁盘空间。Docker Desktop或WSL 2首次安装后可能要求重启Windows；重启后再次双击同一个文件即可继续，不会重复下载已完成的内容。

没有NVIDIA显卡也可以使用。CPU模式功能相同，但CosyVoice生成一句问题可能需要几十秒；建议至少16GB内存和6核CPU。检测到NVIDIA显卡时，安装器会自动使用CUDA版本。

## 启动

电脑重启后，先打开 Docker Desktop，然后双击 `一键启动语音访谈.bat`。程序会启动 CosyVoice 和 SenseVoice，并自动在浏览器打开：

`http://127.0.0.1:8765`

如果两个语音模型已经运行，只需双击 `启动访谈.bat`。使用结束后双击 `停止语音模型.bat` 释放内存。

## 参与者端

1. 点击“开始一次新访谈”。
2. 填写匿名参与者编号，不要填写姓名、身份证号或病历号。
3. 阅读隐私说明，确认麦克风将在访谈期间保持连接，并同意录音。
4. 允许浏览器使用麦克风。
5. AI朗读问题时暂停采集；朗读结束后自动开始聆听，无需逐轮点击录音。
6. 系统检测到参与者开始说话，并在约3.5秒持续安静后自动结束本轮、转写并进入下一轮。
7. 回答过程中可以使用“我说完了”手动结束本轮，也可以随时“暂停聆听”或退出。
8. 完成后，分轮音频、转写和对话记录自动保存在 `data` 文件夹。

浏览器只在参与者回答阶段保存分轮音频，不会把整场环境声音保存为一个不间断文件。麦克风连接状态和录音状态始终显示在页面上。

浏览器意外关闭时，重新打开首页并点击“继续上次访谈”。

## 老师演示模式

首页点击“老师演示模式”即可直接展示程序，不需要允许麦克风，也不会采集真实患者信息：

也可以直接打开 `http://127.0.0.1:8765/?demo=1` 进入演示。

1. 点击“填入示例回答”；
2. 点击“演示实时回应”，查看AI在回答过程中的中性倾听反应；
3. 点击“提交回答，查看下一题”，查看受控追问或进入下一道题；
4. 重复操作直到演示完成。

演示题库位于 `demo_questions.json`，只用于展示交互方式，不是正式研究量表。演示记录不会显示在研究人员后台。正式收集数据前，应由研究团队和伦理审查确认题库内容。

## 研究人员后台

点击右上角“研究人员入口”。原型管理员PIN为 `2468`，正式使用前必须在 `settings.json` 中修改 `admin_pin`。

后台可以查看每次访谈、比较自动转写和人工确认文本、播放回答录音并导出CSV。

## 数据文件

每次访谈使用独立目录：

- `interview.json`：完整会话状态和记录；
- `interview.csv`：每轮问题和回答；
- `question_*.wav`：AI问题语音；
- `answer_*.wav`：参与者回答的标准WAV；
- `answer_*.webm`：浏览器录制的原始文件。

## 本地服务

- 网页平台：`127.0.0.1:8765`
- SenseVoice语音识别：`127.0.0.1:8000`
- CosyVoice语音合成：`127.0.0.1:50000`
- Qwen题库决策：`127.0.0.1:11434`

这些端口都只绑定本机，不对局域网或公网开放。

## 题库与动态互动

系统采用“题库控制研究范围、Qwen控制对话衔接”的方式：

1. `questions.json` 中的核心题目决定必须覆盖的研究主题；
2. 本地Qwen3读取当前问题、参与者回答和下一道核心题；
3. Qwen只选择追问类型，并逐字引用参与者原话；最终问题由经过审核的固定模板组合，不让模型自由编写；
4. 引用不存在、包含诱导表达、格式错误或模型超时时，自动使用固定规则；
5. 每轮的模型来源、动作和理由分别保存为 `dialogue_source`、`dialogue_action` 和 `dialogue_reason`。

考虑到普通电脑显存限制，安装版使用Qwen3-4B处理文本决策，SenseVoice处理语音输入，CosyVoice处理语音输出。这三个组件均在本机运行；以后如果部署完整Qwen-Omni服务器，只需替换对话服务层，无需改题库和数据格式。

## 实时语义回应

录音期间，浏览器在自然停顿处截取最近一小段语音。片段临时送给本机SenseVoice转写，再由Qwen从固定回应中选择：不回应、“嗯，我在听”、“没关系，您可以慢慢组织”、“好的，请继续”或“谢谢您愿意说明这些”。模型不能自由生成实时话语，也不能在患者说话中途追加问题。

临时片段完成分析后立即删除；整段原始录音照常保存。每次回应的时间、局部转写、选择来源和理由会写入 `backchannels`。一轮最多回应两次，重复回应会被抑制。可在 `settings.json` 中把 `realtime_semantic_enabled` 改为 `false`，用于无回应对照条件。

## 研究限制

- ASR可能识别错误，提交前必须人工核对。
- 核心访谈范围由题库决定；本地Qwen根据回答选择非诱导追问或自然进入下一题。
- Qwen不可用或输出不合规时自动改用可审计规则，不会中断访谈。
- 回答过程中的语义回应来自固定语句且最多两次，其内容、时间、局部转写和决策理由均写入数据；正式研究应固定参数并做预实验。
- 检测到明显安全风险词时停止自动访谈，由研究人员接管。
- 正式研究前必须完成题库审查、模拟测试、伦理审批和数据管理方案。
- 流畅度统计与t检验属于后续分析，不应直接显示给参与者。

标注和训练原则见 `数据标注与训练说明.md`。

## 完整版大模型训练代码

`training/qwen3_full/` 提供根据正式访谈题纲整理的 Qwen3-8B 训练管线，包括：

- 机器可读访谈题纲和虚构格式样例；
- 按参与者隔离的训练、验证、测试集生成；
- 标签、直接身份信息、诱导性表达和数据泄漏检查；
- Qwen3-8B 全参数 SFT、单卡 QLoRA、适配器合并与最终测试；
- 联网下载、离线导入、环境安装和训练命令。

完整操作步骤见 `training/qwen3_full/README_CN.md`。仓库不包含模型权重、真实患者数据或训练结果；示例数据不能用于研究结论。
